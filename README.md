# Oficina Pro

A simple Node.js application to manage a mechanical workshop, including a Kanban‑style patio, service orders (OS), and a printable **Laudo** (PDF) with customizable visibility of sections (photos, DTCs, notes, etc.).

## Prerequisites
- **Node.js** (v18 or newer) – the app runs with the built‑in `http` module, no external dependencies.
- **Git** – to push the code to a remote repository (GitHub, GitLab, etc.).
- Optional: **Docker** – for containerised deployment.

## Quick start (local)
```bash
# Clone / copy the project folder
cd oficina
npm install   # generates package‑lock (no extra deps today)
npm start      # server starts on http://localhost:3000 (or $PORT)
```
Open `http://localhost:3000` in a browser. The UI lets you create service orders, add diagnostics, toggle items in the Laudo and generate a clean PDF.

## Deploying online
You have several zero‑cost or low‑cost options. All of them respect the `process.env.PORT` variable that the server already reads.

### 1. Deploy with **Railway** (recommended for beginners)
1. Create a free account at <https://railway.app> and click **New Project → Deploy from GitHub**.
2. Connect the repository that contains this folder (you can push the current folder to a new GitHub repo first).
3. Railway automatically detects the `package.json` and runs `npm start`.
4. The platform injects a `PORT` env‑var, so the app will be reachable at `https://<your‑project>.railway.app`.
5. (Optional) Add a **Persistent Disk** to keep `oficina.db` between restarts – otherwise the SQLite file will be reset on each deploy.

### 2. Deploy with **Render**
1. Sign in at <https://render.com> → **New → Web Service**.
2. Link your GitHub repo.
3. Set **Build Command**: `npm ci` (or `npm install`).
4. Set **Start Command**: `npm start`.
5. Render provides a `PORT` env‑var; the app will be reachable at the URL shown after the build succeeds.
6. Add a **Disk** (e.g., 1 GB) to persist the SQLite database.

### 3. Deploy with **Fly.io** (Docker based, more control)
```bash
# Install flyctl first
curl -L https://fly.io/install.sh | sh
fly auth login
fly launch        # follow prompts – choose a name, region, and set Dockerfile as the build source
fly deploy        # will build the Dockerfile we added and start the service
```
Fly automatically sets `PORT`. You may also attach a volume to persist the DB:
```bash
fly volumes create oficina-data --size 1 --region <region>
fly deploy --mount source=oficina-data,target=/app
```

### 4. Deploy to **Docker Hub / any container host**
```bash
# Build the image locally
docker build -t oficina-pro .
# Run it (Docker will map the internal 3000 port to a host port of your choice)
docker run -d -p 8080:3000 --name oficina-pro oficina-pro
```
Open `http://localhost:8080`. To keep the SQLite file across restarts, mount a host directory:
```bash
mkdir data && docker run -d -p 8080:3000 \
  -v $(pwd)/data:/app \
  --name oficina-pro oficina-pro
```

### 5. Deploy on **Vercel** (static‑only) – *not recommended*
Vercel’s filesystem is read‑only at runtime, so SQLite cannot be written. Use this only for a demo of the static UI; for a production service pick one of the options above.

## Environment variables
| Variable | Description |
|----------|-------------|
| `PORT`   | Port the server should listen on (provided by the platform). |
| `NODE_ENV` | Optional, defaults to `production`. |
| `DATABASE_PATH` (optional) | If you want to store the SQLite file somewhere else, set this variable and modify `db.js` accordingly. |

## PDF customizer
The Laudo page (`public/laudo.html`) contains a **control panel** that lets the user hide/show:
- Queixa / Descrição
- Notas
- DTCs
- Fotos (individual toggles per image)
- Pendências
- Termo/Assinatura
When printing (Ctrl‑P) the hidden elements are excluded, giving a clean A4 PDF for the client.
